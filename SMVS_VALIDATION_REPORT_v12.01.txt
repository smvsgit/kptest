v12.01 STABILIZATION FIXES PRESENT IN SOURCE
1. UAT execution and sign-off are now bound to the exact currently running application version through executed_app_version and approved_app_version.
2. Changing a UAT result clears approval; a prior-release execution cannot be signed off for the current release.
3. Readiness snapshots and go-live review records now persist app_version for traceable release evidence.
4. The readiness version check is dynamic (VERSION must match config version) rather than hard-coded to 12.00, so a legitimate minor stabilization release can pass the version gate.
5. Backup creation now treats failed automatic checksum verification as a failed backup run instead of silently accepting a nominally successful archive.
6. A Passed restore-test can be recorded only against a successful, checksum-verified backup.
7. Go-live restore evidence must come from a verified backup whose manifest app_version matches the current release.
8. Backup readiness now cross-checks verified backup state, configured responsible owner, retention policy, RPO/RTO values and formal accepted-risk decisions where policy remains intentionally unresolved.
9. Production upload readiness now cross-checks the actual configured maximum upload size; an unlimited application setting requires formal accepted-risk evidence to satisfy readiness.
10. Resolved or Risk Accepted Management dependencies require a nonblank written decision/owner/approval-reference note.
11. Planned go-live date is validated as a date rather than accepting arbitrary text.
12. The UAT UI prevents Sign Off while local case changes are unsaved or execution evidence belongs to another release.
13. UAT/readiness CSV export includes executed/approved release fields and a versioned filename.
14. Tests were added/updated for release-bound sign-off, mandatory Management decision notes and prevention of Passed restore evidence on an unverified backup.
