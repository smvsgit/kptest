કાર્યાલય પોર્ટલ - User Guide Manual

Application Release: v15.00

Purpose: Portal users, Department Admin અને Super Admin માટે step-by-step operational guide.

આ manual portalમાં role અને Super Admin દ્વારા નક્કી કરાયેલા page-rights મુજબ જ દેખાય છે. HTML/Word manual download પણ એ જ server-side access rules હેઠળ રહે છે.

પાનું 1 - Getting Started, Navigation અને Page Rights

કાર્યાલય પોર્ટલનું મુખ્ય કામ સંસ્થાના digital files/assets ને centralized, secure અને searchable interfaceમાં ઉપલબ્ધ કરવાનું છે. v15.00માં sidebar/page visibility હવે assigned Portal Roleના page rightsથી governed છે.

Login પછી શું દેખાશે?

  • Browse Files: Search, filters, favorites, recent અને preview.
  • Batch Upload: Upload permission અને Upload page right બંને ધરાવતા users માટે.
  • Access Requests: Protected access request/review.
  • Dashboards & Reports: Role/page-right મુજબ metrics અને exports.
  • Integrations & Health: Authorized Admin માટે source/storage health.
  • User Guide Manual: Manual access policy અને Guide page right બંને લાગુ પડે છે.
  • Settings: Super Admin/eligible Department Admin administration.
Navigation rule: Sidebar menu click પછી URLમાં ?panel=... બદલાય છે. Refresh/Back/Forward selected panel જાળવે છે. Assigned roleમાં page disabled હોય તો menu hidden રહે અને direct panel load Browse પર પાછું જાય છે.

Profile અને Color Theme

Profileમાં language, Change Password, 2FA, Network Access summary અને personal color theme પસંદ કરી શકાય છે. SMVS Teal, Slack Inspired અને Google Inspired themes user accountમાં save થાય છે.

પાનું 2 - Login, Password Reset, Change Password અને 2FA

  1. Portal URL ખોલો અને registered email/password દાખલ કરો.
  2. Password ભૂલાઈ ગયો હોય તો Forgot Password પસંદ કરો.
  3. Admin દ્વારા new user બનાવ્યા પછી setup/reset link emailમાં મળી શકે છે.
  4. Profile → Change Password દ્વારા signed-in user પોતાનો password બદલી શકે છે.
  5. જો 2FA policy mandatory હોય તો TOTP setup/challenge પૂર્ણ કરો.

Admin Password Reset

Super Admin કોઈપણ active userને reset email મોકલી શકે છે અને bulk reset પણ કરી શકે છે. Department Admin પોતાના departmentના eligible userને reset email મોકલી શકે છે. Adminને userનો password જાણવાની જરૂર નથી.

2FA Setup

Profile → Two-Factor Authenticationમાંથી QR/secret setup કરો, code confirm કરો અને recovery codes સુરક્ષિત સ્થળે રાખો.

Security: Reset token single-use/expiry rules હેઠળ છે. Recovery codes અને password reset links share ન કરો. Disabled/Inactive account login કરી શકતું નથી.

પાનું 3 - Browse, Search, Filters, Favorites અને Recently Viewed

Browse Files portalનું primary discovery area છે. Search bar filename, keywords, tags અને configured metadata પર કાર્ય કરે છે.

Recommended Search Flow

  1. Search barમાં keyword લખો.
  2. Scope: Everywhere અથવા Current Department પસંદ કરો.
  3. Type, Department, Access Policy, Year, Event, Location, Owner, Source, Status અને Language filters લાગુ કરો.
  4. જરૂરી filter combination વારંવાર વાપરવો હોય તો Saved Search તરીકે save કરો.

Quick Views

  • Favorites: Star/bookmark કરેલ assets.
  • Recently Viewed: તમે તાજેતરમાં ખોલેલા assets.
Search engine unavailable હોય તો application DB fallback વાપરી શકે છે; Integrations/Health અને readiness panelમાં degraded state ચેક કરો.

પાનું 4 - Preview, Streaming અને Download Controls

File card/open actionથી Preview modal ખૂલે છે. Images, supported documents/PDF, audio અને video માટે preview/streaming શક્ય છે.

ActionMeaning

View permission હોય એટલે Download permission automatic નથી. Protected file માટે approval scope ધ્યાનમાં લો.

પાનું 5 - Access Policy અને Protected Request Workflow

PolicyPortal Behaviour
PublicRegistered internal users માટે policy મુજબ visible/accessible; public internet માટે નહીં.
ProtectedMetadata visible થઈ શકે, content approval સુધી locked.
PrivateUnauthorized department/users માટે record hidden.

Request Access

  1. Protected asset ખોલો અને Request Access પસંદ કરો.
  2. Reason/Purpose લખો.
  3. View Only અથવા View + Download પસંદ કરો.
  4. Department Admin/Super Admin decisionની રાહ જુઓ.
  5. Approve/Reject/More Information result Notification Centerમાં જુઓ.

Temporary approvalમાં expiry હોઈ શકે છે. Expiry પછી entitlement automatically revoke થાય છે.

પાનું 6 - Batch Upload અને Large File Handling

Upload panel Super Admin, Department Admin અને Department Operator જેવા permitted roles માટે ઉપલબ્ધ છે.

  1. એક કે વધુ files પસંદ કરો.
  2. Common metadata: Category, Event, Year, Location, Language વગેરે ભરો.
  3. Required fields red/required marker મુજબ પૂરા કરો.
  4. Queue શરૂ કરો. દરેક fileનું size, progress %, status અને retry controls જુઓ.
  5. Large file threshold ઉપર resumable/chunk upload automatically વપરાઈ શકે છે.
Persistent bytes: Actual uploaded source files /var/www/html/storage/app/media/uploadsમાં લખાય છે, જે Coolify hostના /srv/media/projects/karyalayportal/uploads સાથે bind-mounted છે.
Browser close/network interruption પછી resumable status ઉપલબ્ધ હોય તો Retry/Resume વાપરો. Duplicate warning આવે તો existing asset તપાસ્યા વગર auto-delete ન કરો.

પાનું 7 - Metadata, Categories અને Master Data

Structured metadata search, governance અને lifecycle માટે મહત્વપૂર્ણ છે. Required metadata rules Admin દ્વારા configure થઈ શકે છે.

Common metadata

  • Owner Department, Uploader, Category/Sub-category
  • Year, Country, State, City, Mandir
  • Event/Prasang, Guruji/Person, Language, Media Type
  • Description, Internal Remarks, Tags
  • Access Policy, Download Allowed, Lifecycle Status

Master Data values Super Admin દ્વારા Settings → Metadata & Master Dataમાંથી manage થાય છે. Parent hierarchy (Country → State → City → Mandir) validate થાય છે.

પાનું 8 - Folders, Collections અને Related Assets

Portalમાં flat files સિવાય logical organization ઉપલબ્ધ છે.

  • Folder: Department-scoped operational grouping.
  • Collection: Curated set of related assets.
  • Event/Prasang: Event metadata દ્વારા cross-media grouping.
  • Related Assets: Video ↔ Audio ↔ Photo ↔ Poster ↔ Document links.
Related asset link content bytes duplicate કરતું નથી; logical relationship બનાવે છે.

પાનું 9 - Lifecycle, Versioning અને Recycle Bin

Governed lifecycle default workflow: Draft → Review → Approved → Published → Archived. Allowed transitions Admin policy મુજબ enforce થાય છે.

Versioning

  • Replacement version history immutable રહે છે.
  • Changed By, Changed Date, Change Note capture થાય છે.
  • Previous version restore કરવાથી નવો current version બને છે; old history destroy થતી નથી.

Recycle Bin

Normal delete soft-delete છે. Retention period દરમિયાન restore થઈ શકે છે. Permanent delete elevated authorization + audit હેઠળ છે.

Bulk Editથી lifecycle status bypass કરવાનો પ્રયાસ ન કરો. Lifecycle status dedicated transition actionથી જ બદલાય છે.

પાનું 10 - Notifications, Preferences અને Escalation

Portal Notification Center unread/read state જાળવે છે. Configured provider મુજબ Email, WhatsApp અને Text SMS delivery પણ શક્ય છે.

  • Access request alerts
  • Approve/Reject/More Information result
  • File update/broken source/storage warning
  • Security/administrative alerts

Profile/preferencesમાં user allowed channels પસંદ કરી શકે છે; Central Admin master switch અંતિમ authority છે. Pending approvals માટે escalation scheduler configure કરી શકાય છે.

પાનું 11 - Dashboards, Reports, Exports અને Scheduled Reports

Dashboard content role-aware છે. Reportsમાં access/download, activity/security, storage, users, pending approvals અને operational data સામેલ થઈ શકે છે.

Exports

Authorized reports CSV/XLSX અને browser Print/Save PDF દ્વારા export થઈ શકે છે.

Scheduled Reports

  1. Super Admin Reports panelમાં Scheduled Reports section ખોલે.
  2. Weekly/Monthly frequency, report type, output format અને recipients configure કરે.
  3. Schedule enable/pause કરી શકાય.
  4. Manual Run દ્વારા તરત run test કરી શકાય.
  5. Run history, SHA-256 અને download output review કરો.

પાનું 13 - Department Admin Operations અને Scoped User Management

Department Admin પોતાના department scopeમાં content, approvals, selected user management અને health visibility સંભાળી શકે છે. Super Admin page-rights અથવા policies દ્વારા કેટલીક admin capabilities restrict કરી શકે છે.

Daily checklist

  • Pending Protected Access requests review
  • Recent uploads/metadata/lifecycle quality check
  • Broken/Missing source અને quota warnings review
  • Department activity/report review
  • Department users/groups/roles review where Settings access is enabled

User management boundary

Department Admin પોતાના departmentમાં users create કરી શકે છે, approved Operator/Viewer-based Portal Roles assign કરી શકે છે અને password reset email મોકલી શકે છે. Super Admin policy enabled હોય ત્યારે જ Department Admin external Internet exception manage કરી શકે છે; Admin-level rolesને elevate/change કરી શકતો નથી.

પાનું 17 - User Guide Manual Access Rights

Super Admin Settings → User Guide Accessમાંથી manual કોને દેખાડવું અને કેટલા logical pages સુધી access આપવો તે configure કરી શકે છે.

Priority order

  1. User override - specific user માટે 0 થી 22 pages.
  2. Department override - department માટે 0 થી 22 pages.
  3. Role default - Department Admin / Operator / Viewer માટે 0 થી 22 pages.

0 pages = manual hidden. Super Adminને recovery/governance માટે full 22 pages હંમેશા ઉપલબ્ધ રહે છે.

Existing deploymentsના configured page counts preserve થાય છે; Super Admin નવા v15 chapters expose કરવા role/department/user counts વધારી શકે છે.

HTML print view અને full Word manual download server-side entitlementથી protected છે. Partial-access userને complete DOCX download મળતું નથી.

Development coding complete હોવું Go-Live approval નથી. All P0 UAT, backup/restore evidence, approved policy values અને readiness review પછી જ Go-Live Done mark કરવું.

પાનું 19 - User Management

Settings → Users & Roles panelમાંથી authorized admins user lifecycle manage કરે છે.

Create User

  1. Name, email, phone (optional), department અને organization unit પસંદ કરો.
  2. Portal Role પસંદ કરો.
  3. Create User કરો. System random internal credential બનાવે છે અને userને password setup/reset link email કરે છે.
  4. User login પહેલાં email delivery અને account status verify કરો.

Status અને Password Reset

  • Super Admin: all users enable/disable/inactive, individual password reset email, bulk reset email.
  • Department Admin: own department users create/reset within policy scope.
  • User: Profileમાંથી own Change Password.
Admin દ્વારા plain-text permanent password set/share કરવાને બદલે reset-link flow વાપરવો. Disabled userના active sessions revoke થાય તે security behavior verify કરો.

પાનું 20 - Role Management અને Page Rights

Built-in roles Super Admin, Department Admin, Department Operator અને Viewer છે. Super Admin built-in roleના page access અને least-privilege permission limits edit કરી શકે છે. Built-in base role deactivate/delete કરી શકાતો નથી.

Custom Role

  1. Role name અને security base role પસંદ કરો.
  2. Allowed pages પસંદ કરો: Browse, Upload, Access, Reports, Integrations, Guide, Settings.
  3. Permission limits પસંદ કરો.
  4. Create પછી users/groupsને role assign કરો.
Security model: Custom role base roleથી વધારે privilege આપી શકતું નથી. UI permission checkbox accidental elevation કરતું નથી; backend legacy/base role maximum authority તરીકે enforce કરે છે.

Browse page always available રહે છે. Super Admin Settings self-lockout રોકવા Settings page always available રહે છે.

પાનું 21 - User Groups અને Group-wise Role Assignment

User Group department/team-based administration સરળ બનાવે છે.

  1. Group name, department અને desired Portal Role પસંદ કરીને group બનાવો.
  2. Eligible usersને groupમાં add કરો.
  3. જરૂર હોય તો Apply Group Roleથી active membersને role apply કરો.
  4. Role change પછી user access/menu verify કરો.

Department Admin પોતાના department સુધી scoped છે અને Operator/Viewer-based role સુધી મર્યાદિત છે. Super Admin cross-department/global role governance કરે છે.

Group membership પોતે security elevation નથી; applied role અને user base authorization backendમાં ફરી validate થાય છે.

પાનું 22 - External Internet Access અને Network Decision Logic

Recommended production posture Internal / VPN Only છે. Same portal URL internet પરથી reachable રહી શકે છે, પરંતુ application requestના network source અને user entitlement મુજબ access આપે છે.

Source / User stateResult
IP approved Internal CIDRNormal access, subject to login/role/2FA.
IP approved VPN rangeNormal VPN access.
External Internet + active user exceptionAllowed during configured start/expiry window.
External Internet + no/expired exceptionBlocked.

Grant / Revoke

Super Admin User Managementમાં External Internet Access Allowed/Blocked, optional Start, Expiry અને mandatory Reason configure કરે છે. Approved By automatically audit contextમાં capture થાય છે. Revocation active sessionsને invalidate કરે છે.

Department Adminને આ right માત્ર Super Adminના Allow Department Admin to manage external access policyથી મળે છે; તે own departmentના eligible non-admin users સુધી જ મર્યાદિત છે.

Login auditમાં request source Internal, VPN, External Internet અથવા unrestricted policy state તરીકે record થાય છે. Expiry request-time enforce થાય છે; schedulerની રાહ જોવી પડતી નથી.
