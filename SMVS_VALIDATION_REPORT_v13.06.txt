OBSERVED RUNTIME SYMPTOMS
- The deployed v13.05 application loads Browse Files normally.
- Clicking sidebar modules can leave the page as a uniform dark/blank screen.
- The sidebar/header/application shell disappears, which is consistent with the React root being lost after an uncaught client-side exception rather than a normal panel CSS visibility issue.
- The URL does not change when a module is selected.
- Refresh returns to Browse Files because the selected module was held only in React local state.

FIRST SOURCE-LEVEL ROOT CAUSE / FAILURE CLASS
- Dashboard.tsx used local useState('browse-panel') for the selected sidebar module; sidebar clicks only called setActiveTab and therefore produced no navigable URL state.
- All six non-Browse sidebar modules were dynamically imported with React.lazy and rendered inside Suspense with fallback={null}.
- There was no React ErrorBoundary around the dashboard panels.
- Consequently, a lazy-chunk load failure OR a render-time exception in one of those dynamically mounted panels could escape the panel, unmount the React application shell, and leave only the dark body background. Because the module selection was not URL-backed, refresh reset to Browse Files.
- The supplied screenshot does not include browser-console/network evidence, so this validation does not invent a specific HTTP status or exact JavaScript exception. The fix removes the critical lazy-chunk dependency from sidebar navigation and adds error containment for any remaining render exception.

FIXES APPLIED
1. Critical sidebar modules are now eager/static imports in Dashboard.tsx:
   - Batch Upload
   - Access Requests
   - Notifications
   - Dashboards & Reports
   - Integrations & Health
   - Settings
   Heavy modals remain lazy-loaded.
2. Added URL-backed panel navigation using the panel query parameter:
   - ?panel=upload
   - ?panel=access
   - ?panel=notifications
   - ?panel=reports
   - ?panel=integrations
   - ?panel=settings
   Browse Files uses the clean root URL.
3. DashboardController now includes panel in FILTER_KEYS so Inertia returns/preserves the selected panel state.
4. Dashboard active panel is derived from filters.panel instead of ephemeral local activeTab state.
5. Sidebar panel switching uses an Inertia GET partial reload for filters, so the browser URL, refresh behavior, and Back/Forward history represent the selected module.
6. Browse/search/category/saved-search actions clear panel and intentionally return to Browse Files.
7. Added PanelErrorBoundary.tsx. If a panel throws during rendering, only that panel shows an error card and a Return to Browse Files action; the sidebar/header shell remains mounted instead of becoming a blank page.
8. Preserved v13.05 Coolify APP_KEY/cache permission fix and all existing completed features/data architecture.
9. Preserved persistent media bind mount on app + worker + scheduler:
   /srv/media/projects/karyalayportal/uploads:/var/www/html/storage/app/media/uploads
