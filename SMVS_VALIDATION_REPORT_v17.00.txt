APPLICATION DEFECTS FIXED
- JSON error rendering was restricted to api/* routes, so every in-portal fetch caller
  received a 302 HTML redirect instead of a 422/403 body. A failed action could therefore
  report success while nothing was saved. This was the shared root cause behind the
  "user created but not in the list" (C01) and "2FA not working" (C17) reports.
- Bulk department transfer always failed: Rule::exists(...)->where('is_system', false)
  serialises boolean false to an empty string and matched no row.
- XLSX user import compared a SimpleXMLElement attribute with ===, so shared strings were
  never resolved and every imported row was skipped.
- Protected content was openable by any member of the owning department. BR-02 is now
  enforced: content stays locked until an access request is approved. Super Admin, the
  owning department's admin and the asset owner retain direct access.
- Images whose thumbnail job had not run showed a broken placeholder; the original file
  is now served as a fallback.
- The header Sun/Moon control is now a session-level mode override, so opening Profile no
  longer reverts a light/dark choice.

FUNCTIONAL SCOPE
- Category and sub-category: drawer menus for both levels, parent-first creation flow,
  rename and re-parent, live search, duplicate-safe naming.
- Master Data Management: one form per type, parent selection only where the hierarchy
  requires it, per-type search, inline edit, parents shown by name.
- Department storage quotas: per-department limits with live usage, meter and
  Within/Near/Reached state; blank follows the default, 0 GB means unlimited.
- Batch Upload: inline master-value creation for Super Admin and Department Admin;
  queue and shared metadata reset after a successful batch, failed items retained.
- User groups: inline rename/re-role/deactivate and a filterable member picker.
- Departments: usage counts shown and deletion blocked while users, assets or
  sub-departments depend on them.
